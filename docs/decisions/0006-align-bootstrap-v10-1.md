# 0006 — Align context architecture with bootstrap v10.1

Date: 2026-09-22
Status: Accepted
Decision: Adopt bootstrap v10.1 conventions on top of the existing v9-style structure: add `docs/ARCHITECTURE.md`, `docs/SECURITY.md`, `docs/DEBUGGING.md`, `docs/_templates/`, `docs/decisions/` (one file per decision + `INDEX.md`), `.env.example`, `.claude/settings.json`, `.gemini/settings.json`. Add Task levels (L0-L2) and a Commands table to `AGENTS.md`. Restructure `STATE.md` to the new field layout. Trim `docs/BACKLOG.md` (drop Done, fold Later into Next).
Context: The repository already had a v9-style protocol (`AGENTS.md`, `docs/TECH.md`, `docs/PRODUCT.md`, `docs/BACKLOG.md`, `docs/DECISIONS.md`, `docs/RUNBOOK.md`, thin routers). The user asked to apply `bootstrap-prompt_v10.1.md`.
Rationale: v10.1 adds explicit security/debugging docs, atomic per-decision files, and task-level classification without requiring a code reorganisation. "Keep what works" — `docs/TECH.md` and `docs/PRODUCT.md` remain the read-only technical/product references; `docs/DECISIONS.md` is kept until the user confirms deletion in favour of `docs/decisions/`.
Consequences: `docs/TECH.md` is NOT merged into `docs/ARCHITECTURE.md` and NOT deleted — it stays as the detailed technical reference (read-only), since it is marked read-only in `AGENTS.md` and its content (file structure, key flows, full DB schema, Enable Banking API notes, bugs-fixed list) exceeds `ARCHITECTURE.md`'s scope. `docs/ARCHITECTURE.md` holds only the Stack table and module-map note, and points to `docs/TECH.md` for detail. `CLAUDE.md`, `GEMINI.md`, `.cursor/rules/000-router.mdc`, and the original `docs/DECISIONS.md` are kept pending explicit user confirmation to delete.
Alternatives_Rejected: Force-merging `docs/TECH.md` into `docs/ARCHITECTURE.md` and deleting it — rejected because it is a read-only file requiring explicit authorisation, and the merge would either lose detail or bloat `ARCHITECTURE.md` beyond its intended scope.
